# Состав сервисов и распределение ответственности

Размер команды не задан. Базовый план — 3 участника и 6 сервисов (по 2 на каждого).

| Участник | Сервисы | Ответственность |
|---|---|---|
| 1 | Users, Rooms | Роли, токены, аудитории, каталог и кэш |
| 2 | Equipment, Bookings | Инвентарь, интервалы, конкурентность и outbox |
| 3 | Notifications, Audit | Inbox, consumer deduplication, архив |

Это распределение работ, не утверждение о фактическом составе команды. Для 4–6 человек шесть сервисов обеспечивают минимум один сервис на человека; предпочтительные два требуют расширения. Для команды >6 человек минимум пока не выполнен: нужно добавить сервисы с реальной отдельной ответственностью.

Возможные расширения: Availability (расписание занятий), Maintenance (обслуживание оборудования), Approval (согласование специальных ресурсов), Reminders (планирование напоминаний), Analytics (загрузка аудиторий), Access (QR-пропуска). Не следует искусственно считать инфраструктуру Kafka/Valkey/Nginx отдельными бизнес-микросервисами.

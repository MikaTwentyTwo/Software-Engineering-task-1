# Проверки и приёмка

## Выполнено в среде подготовки

- 10 unittest-проверок: нормализация часового пояса, отказ для некорректных интервалов, полуоткрытые границы, правила ресурсов, подпись/искажение/экспирация токена.
- Синтаксическая компиляция всех Python-модулей.
- Разбор Compose и workflow как YAML, проверка сервисов, связей и обязательных файлов.

## Не выполнено в среде подготовки

Docker отсутствует; полный Compose, реальные PostgreSQL/Kafka/MongoDB/Valkey и HTTP integration test здесь не запускались. Не заявляется успешный запуск контейнеров, нагрузочные показатели или HA. GitHub Actions запустится только после загрузки и при доступности Actions для репозитория; его результат необходимо проверить отдельно.

## Автоматизированная проверка на стенде

scripts/demo.py проверяет живой API: вход, роли, проекции ресурсов, идемпотентность, конфликт, собственные уведомления, аудит, повторную отмену, конкурентную гонку двух запросов и права владельца. CI содержит unit и integration jobs. Самый важный критерий — один успех и один конфликт для двух одновременных пересекающихся броней.

## Дополнительная приёмка

| Проверка | Действие | Ожидание |
|---|---|---|
| Kafka outage | Остановить Kafka после запуска; создать бронь; восстановить Kafka | Бронь committed, затем приходит уведомление |
| Consumer crash | Остановить notifications; создать бронь; запустить снова | Уведомление приходит по сохранённому offset |
| Replay | Вернуть offset notifications назад в пределах retention | Старые event_id не создают второе уведомление |
| Cache outage | Остановить Valkey; читать каталог | Чтение из PostgreSQL успешно |
| Архив | На тестовом audit задать ARCHIVE_AFTER_DAYS=0 | Через цикл событие в /archive, исчезает из /events |
| Rate limit | >30 запросов в коротком burst с одного IP | Часть ответов 429 |
| Backup recovery | Восстановить дампы на чистом стенде | Брони и аудит соответствуют данным backup |
| Capacity | 100 конкурентных броней одного интервала | Ровно одна confirmed, остальные 409; limiter настроить отдельно |

Остановка gateway не отменяет уже committed-операции. Для повторного запроса после сетевой ошибки клиент сохраняет Idempotency-Key. Дополнительные проверки перечислены как план, а не как выполненные.

# HAProxy + Keepalived: проверка переключения

Два контейнера HAProxy + Keepalived работают в Docker-сети campus:

- lb1: 192.168.49.10, приоритет 150.
- lb2: 192.168.49.11, приоритет 100.
- Виртуальный IP: 192.168.49.250.
- Вход с Windows: http://127.0.0.1:18080.
- Контейнер access перенаправляет TCP-трафик на виртуальный IP.
- HAProxy направляет запросы на Istio Gateway NodePort 31776.
- Проверка готовности Gateway выполняется через порт 32697.

## Запуск

Из корня репозитория:

    docker build -t campus-ha:dev-001 platform/ha
    docker compose -p campus-ha -f platform/ha/compose.yaml up -d

Docker-сеть campus и кластер должны быть запущены.
Локальный порт 18080 должен быть свободен.

## Результаты проверки 2026-10-06

1. В штатном состоянии VIP принадлежит только lb1.
2. При остановке lb1 VIP переходит на lb2.
3. В первом тесте один запрос завершился таймаутом 3 секунды,
   следующие девять получили HTTP 200 через campus-lb2.
4. После исправления хранения PID-файлов повторный тест:
   через 5 секунд после остановки — HTTP 200 через campus-lb2;
   через 8 секунд после запуска — HTTP 200 через campus-lb1.
   Эти интервалы являются задержками проверки, а не точным
   измерением времени переключения.
5. Полный scripts/demo.py прошёл через резервный lb2.

Для обоих балансировщиков /run размещён в tmpfs, чтобы PID-файлы
Keepalived не сохранялись между запусками контейнера.

## Ограничения

Проверена отказоустойчивость пары балансировщиков.
Компьютер, Docker Desktop, контейнер access и единственный узел
Kubernetes остаются общими точками отказа.
Автоматическое масштабирование worker-узлов этой схемой не реализовано.
